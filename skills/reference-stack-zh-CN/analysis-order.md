# MDS/PCA → DEG → 火山图/MA → GO/KEGG：实际执行与验收顺序

对应英文入口：[reference-stack/analysis-order.md](../reference-stack/analysis-order.md)。

## 结论

这不是一条把所有图表串起来的流水线，而是一条有统计依赖关系的证据链：

```text
输入合同与原始 QC
    ↓
样本层 MDS/PCA（诊断批次、离群和主要变异）
    ↓
DEG 模型与预先声明的 contrast（唯一主要推断节点）
    ↓
冻结完整 DE 表
    ├── 火山图 / MA / 热图（表达分支）
    └── GO / KEGG：先选 ORA 或 GSEA，再做富集（解释分支）
    ↓
ID 映射、universe、数据库快照、provenance
    ↓
在独立复现或 holdout 上关闭 Claim
```

## 每一步在验证什么

### 0. 输入合同和原始 QC

记录物种、测序/芯片类型、原始或已归一化矩阵、样本元数据、组别、批次、性别、
重复结构、基因 ID 类型、缺失值处理和软件版本。样本 ID 必须一一匹配；每个比较组
应达到预先规定的最小重复数。没有这些信息，后续 p 值不能被当作可审计结果。

### 1. MDS/PCA：先做样本诊断

bulk RNA-seq 常用 log/VST 后 PCA；如果合同明确使用 classical MDS，就写明距离定义、
距离矩阵和 `n_components`。颜色和形状分别标出 biological condition、batch 等元数据，
并保留方差解释率、距离矩阵、载荷和随机种子。t-SNE/UMAP 适合局部结构展示，不能把
二维簇间距离或点密度直接解释成生物学事实。

MDS/PCA 的验收不是“图看起来漂亮”，而是：样本数和标签正确、批次是否主导 PC/MDS 轴
已被记录、离群样本是否有预先规定的处理、是否保留了可重算的中间对象。

### 2. DEG：唯一的主要统计推断节点

- raw counts：优先 DESeq2 或 edgeR；已归一化连续表达：limma/voom 或明确的等价模型。
- 设计矩阵、contrast、参考组、协变量、归一化、过滤规则和多重检验方法必须冻结。
- 使用 BH/IHW 等 FDR 控制时，记录其适用前提；不要把事后 `abs(LFC)>1` 误写成已控制
  了“生物学幅度”的 FDR。若幅度是主要问题，使用预先声明的 TREAT/`lfcThreshold`。
- 输出完整 DE 表：估计值、标准误/统计量、原始 p 值、调整后 p 值、baseMean/丰度、
  过滤或 outlier 原因，以及 session/package 版本。

### 3. 火山图、MA 和热图

这些图是诊断和表达，不是新的统计检验。火山图可同时展示方向和显著性；MA 图检查
效应是否随平均表达量变化；热图只画预先定义的基因集合并清楚说明变换和聚类距离。
作图最好使用收缩后的 LFC 以改善可读性，但 p 值和显著性判断来自原始拟合结果，不能
把收缩后的 LFC 和未经说明的 p 值混成新的检验。

### 4. GO/KEGG 富集

先问输入是否有几乎全部基因的可靠排名：有则走 GSEA；只有预选列表则走 ORA。ORA
必须使用实际可检验基因作为 universe；GSEA 使用排序后的全部可检验基因，不能先砍成
显著列表。GO/KEGG ID、物种代码、数据库版本、访问日期和映射损失都要写入结果。

KEGG 的实时 REST 查询会随时间变化；发表或基准测试应保存 `gson` 快照或等价响应。
富集结果只支持“在指定方法、背景和数据库版本下的关联”，不能单独关闭疾病机制 Claim。

## MVP 最小交付物

1. 输入 schema 与样本映射检查日志。
2. MDS/PCA 对象、图、方差解释率和批次/离群诊断。
3. 冻结的完整 DE 表，以及由它派生的显著列表和排名向量。
4. 火山图、MA 图、热图及其作图参数。
5. GO/KEGG 的 ORA 或 GSEA 结果、ID 映射表、universe、数据库快照信息。
6. 每个 Claim 的方法、阈值、版本、随机种子、命令和输入哈希。
7. no-skill / with-skill、no-Spec / with-Spec 的同数据集对照评分，而不是只展示一张图。
