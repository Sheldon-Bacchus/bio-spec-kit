# [PROJECT_NAME] Constitution

## Core Principles

### I. Evidence Before Interpretation

Every research feature MUST distinguish observed measurements, validation
results, interpretations, and claims. A claim without a traceable evidence
path is not releaseable.

### II. Question and Estimand First

The scientific question, primary estimand, population, sample unit, and scope
MUST be explicit before implementation choices are made.

### III. No Silent Assumptions

Missing thresholds, contrasts, references, causal interpretations, and release
decisions MUST be recorded as assumptions or clarification items. Agents MUST
not silently invent load-bearing choices.

### IV. Deterministic Checks and Human Review

Machine-checkable criteria MUST produce explicit pass, fail, inconclusive, or
not-evaluable results. Human approval is required before consequential
interpretation or release.

### V. Reproducible Identity

Inputs, references, parameters, software versions, and execution identity MUST
be recorded well enough to reproduce or audit the result.

## Research Constraints

- A bounded fixture or dataset MUST be named before execution.
- Exploratory observations MUST NOT be presented as confirmatory evidence.
- Negative, insufficient, and invalid evidence states MUST remain distinct.
- A Preset or Bio Skill MUST NOT be described as scientific validation.
- A Spec Kit template MUST NOT become a method handbook; method ownership stays
  with the referenced Bio Skill.

## Development Workflow

Spec Kit produces reviewed `spec`, `plan`, `tasks`, and checklist artifacts.
The plan records the required capability and `skill_id`; the referenced Bio
Skill owns the scientific method and execution details.

Implementation or execution requires a reviewed feature plan, an available
Bio Skill, and explicit user direction. No Workflow or worker runtime is part
of the BioSpec MVP Preset.

## Governance

This constitution supersedes convenience prompts and generated suggestions.
Amendments require a reviewed change, a version update, and an explanation of
which templates, capability bindings, or validation checks are affected.
